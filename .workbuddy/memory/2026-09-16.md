# 2026-09-16

## WTB 项目前后端架构梳理（分析任务，无代码改动）

- 前端：`web/`（wtb-console-mvp），React 19 + Vite + @xyflow/react，无路由库，单 App.tsx 内 6 个 view（workflow/components/compare/batch/audit/system）。
- 数据流：`service.ts` 封装 fetch `/api/v1/*`（有 body 即 POST），`HttpConsoleService` 用 useSyncExternalStore 提供全局快照；`useRemote.ts` 按 path+revision 拉取详情（执行详情、检查点、操作状态、批量结果）。连接层：WebSocket `/ws` 收到消息后 100ms 防抖触发 refresh，另有 2s 兜底轮询 + 断线 2s 重连。
- 后端入口：`python -m wtb.api.console --data-dir data/console`（FastAPI，端口 8000，uvicorn）。Vite dev 代理 `/api` 和 `/ws` 到 127.0.0.1:8000。
- 核心应用层：`wtb/application/services/console_service.py` 的 `ConsoleService`——SQLite console.db 存储 execution/checkpoint/operation/batch/event/integrity；ThreadPoolExecutor(max_workers=2) 执行操作；操作均为异步 202 模式（返回 operationId，前端轮询 `/operations/{id}`）。
- 每次执行有独立 workspace（`data/console/workspaces/<id>/`，graph.pkl + outputs/），通过 ExecutionControllerFactory + LangGraphStateAdapter 驱动真实执行；节点边界自动打 checkpoint 并 CAS 追踪文件（fileCommitId）。
- 已支持命令：run/pause/resume/stop/rollback/fork/edit(改状态)/checkpoint(手动存档)/breakpoints(断点)。capabilities: local=true, ray/venv/evaluation=false（前端如实显示"本阶段未接入"）。
- 结论/建议：控制台已完整覆盖 WTB 核心卖点（checkpoint、rollback、fork、变体、批量、CAS 文件、审计），主要可补强的是文件版本展示（files API 已有但 UI 较弱）与分支树可视化（branches API 已有）。
